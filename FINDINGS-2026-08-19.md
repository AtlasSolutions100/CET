## F12 — Closed-loop welds + parallel-stagger joins (the "leader line" diagonals)
User's screenshot: phantom dashed diagonal inside the F3.0 footing callout on Belle
Structural p1 (engine p0). Root cause was NOT a leader: `_join_chain_ends` welded two
CLOSED dashed rectangles (native 3 3 footing boxes) end-to-end — a closed stroke's
endpoints coincide, so every join guard reads it as a willing partner, and the join
segment renders as a dashed diagonal. Same mechanism built a 7,060pt mega-chain from
the wall footing strips. Two general fixes in `_join_chain_ends`:
1. closed chains (start≈end, ≥4 pts) never join — a closed rect/loop is a complete feature;
2. path-turn budget: charge turn(va→gap) + turn(gap→vb) against the 100° cap for gaps
   ≥6pt, so two parallel lines with staggered ends (tangent turn 0°, gap 90° sideways)
   can no longer weld into a Z. Tiny gaps and label-bridge/kink rules unchanged.
Verified: diagonal gone at all F3.0 callouts, mega-chain shattered to honest closed
features (3,860pt max, 0 oblique jumps), fireplace footing region faithful.
Leaders themselves emit as separate solid annotation chains (correct); arrowheads are
filled glyphs we do not stroke. Gate: regress + Belle Road eval + GCHC spike scan.

## F15 — chain.py determinism: greedy accept order pinned (gate x2 identical)
Symptom: marginal classes flip between identical-code regress runs (dash3
present/absent on Oncor engine p3 = printed sheet 4). Root cause class: greedy
accept loops inherited iteration order from sources that are deterministic only
by accident of library version — python set iteration, scipy query_pairs
emission order, argsort tie permutation. The flip did NOT reproduce on HEAD
(3 hash seeds, warm cache: Oncor p3 bit-identical, 608 chains, dash3=0 each
time), but bisection proved outcomes DO hinge on those orders: reordering the
twin-merge pair accepts alone moves 2-3 chains dash1<->solid on Belle
Structural p0. Nine edits in chain.py pin every such loop to meaningful order:
stable argsorts (_match_links score ties; twin subsegment sweep), twin pairs
lexsorted by unit index, sorted() on query_pairs iteration (_glyph_blobs,
marker collapse, _join_chain_ends), _bridge_text merge order by chain_id,
sorted pickup/ball-point candidates, sorted dash-text token ties, sorted(drop)
absorb tags. Tie re-breaks moved (probe-verified, seed-stable): Belle p0
366 chains both, dash1 80->78, solid 239->241; Oncor p3 608 both, dash1
231->233, solid 342<-344; dash3 stays 0 on p3 — the class that flickered is
now stably absent there (whether p3 SHOULD have dash3 is a detection question,
not a determinism one; no ground-truth file asserts it). GATE: regress x2
back-to-back, outputs byte-identical after stripping timings — 100% precision
every class/sheet, phantom 0, spikes 3/2/2/2/0/1/3, mean truth accuracy 98.3%
(matches the mid-night reference). Process note: these hunks were swept into
b0bacf0 (CORE rebrand, git add -A) by the parallel session BEFORE the gate
finished; the gate passed after the fact and this entry documents them.

## F22 — Object counting v2: wall-band components (41 -> 9 vs hand count 13)
The user hand-counted 13 shear walls; straight-run counting said 41. General
rules, iterated live against that ground truth: (1) an object is a CLUSTER of
runs that are near AND parallel — the two drawn faces of one wall and its
collinear continuation merge; perpendicular touches (corners, T-junctions)
are different objects; (2) touch tolerance is scale-aware (1.2 ft) so doorway
gaps (>=30 in) split but face pairs merge; (3) parallel face echoes are
deduped from footage (one wall, one length); (4) sub-1.5 ft components are
pattern debris, dropped; (5) same-label object styles pool before clustering
(a wall drawn with two pens is one wall). Belle p2: 41 -> 16 (components per
style) -> 9 (label pool + parallel rule), lengths 40/40/25/25/10/3/3/2/2 ft.
Remaining gap to the human 13 is OPENINGS: drawn lines overshoot wall ends
into doorways, shrinking the gaps below any general threshold — door/window
detection in the ENGINE (swing arcs first) is the named next feature, and it
also fixes footage-over-openings. No per-sheet tuning added.
