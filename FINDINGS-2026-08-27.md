reaches a NUMBER is correct — `computeTakeoffRows` skips `state.excluded`, the

It buys 1.6 ft of correctness and destroys 18,904 ft. It shrinks the sheet's

Compounding it: `_scale_report_lines()` (server.py:1561) builds

vertical scale set, every code path returns the engine's own number untouched,

click, and the click silently rewrites every number on the page.

**Action: gate the control off before anything else.** The proper fix is to
make the vertical scale apply only to chains inside the profile region, which

## 5. TRAPS THAT COST TIME TODAY — you will hit these

* **`sed 's/^/  /'` lies about indentation.** Two patch anchors failed because
  a display prefix made 8 spaces look like 10. Verify anchors with Python
  `repr()`, never by eye off a piped `cat -A`.
* **Heredocs eat backslashes.** `\n` inside a quoted heredoc collapses to a
  real newline and corrupts emitted JS. Write patch scripts with the Write
  tool, or build strings with `chr(10)`.
* **Canvas overlays must apply `IMG_DPI / 72` = 1.80556.** `draw()` renders in
  image-pixel space. An overlay in raw page points lands at ~55% of the true
  position — this produced a wrong "the app and the engine disagree"
  conclusion until an annotated capture showed an empty box.
* **The browser pane needs a second screenshot** after a DOM change; the first
  often catches the pre-paint frame.
* **Never write `state.view` to navigate.** Scroll and drag. Reading app state
  is inspection; writing it is not verification.
* Page numbering: always state engine 0-based index AND printed sheet.
* `get_drawings()` = raw unrotated coords; `get_text()`/`get_pixmap()` are
  rotation-aware. The engine maps geometry through `page.rotation_matrix`, so a
  `get_pixmap` clip in `page.rect` space matches engine coordinates.
* Cached results under `C:/Users/kobys/takeoff-jobs/` may be STALE (their
  `engine_sig` predates `c5ee78216dac903c`). Check before trusting one.

## 8. CORRECTION — `_ENGINE_FILES` is right; do NOT "fix" it

The independent audit flagged that `earthwork.py` and `profile.py` are absent
from `_ENGINE_FILES` (detect_page.py:50), concluding that a fix to earthwork
would ship while caches served the old numbers as fresh. I confirmed the
absence and repeated the conclusion. **The conclusion is wrong.** Checked:

```
detect_page.py imports profile / earthwork / overlay / visibility : NONE
profile.py     imported by anything in takeoff_engine/            : nobody
earthwork.py   imported by anything in takeoff_engine/            : nobody
overlay.py     imported by                    batch/cli/milestone_report only
```

Nothing those modules produce enters `p<N>_result.json`, which is the only
thing `engine_sig` gates. `/confidence` imports `read_spot_datum` and calls it
**at request time** (server.py:1287, :1306) and writes no cache. So:

* The A1 datum fix needs **no** cache invalidation. It takes effect on the
  next request.
* Adding those files to `_ENGINE_FILES` would stale every cached page on dev
  and production, force a full re-detect, and produce byte-identical line
  detection. Pure cost.

Second-order trap for whoever reads this next: `engine_sig` hashes file
CONTENT, and `detect_page.py` is itself in the list — so even adding an
explanatory comment there triggers a full corpus re-detect. If you are editing
`detect_page.py` for another reason anyway, add a line recording why these four
are excluded. Do not touch it solely to document this.

`p<N>_elevgaps.json` has no version guard, which is correct: it caches OCR of a
fixed raster, which is deterministic and independent of engine logic. Changing
how a datum is *resolved* does not change what the OCR *read*.
