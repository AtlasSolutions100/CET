## F67 — Bill's coloured markings are an ANSWER KEY, not a feature to detect

Koby clarified that "Marked Up Window Plans - Aqua Vista" is Bill demonstrating his
own estimating method. Verified on the sheet: the cyan swipe sits **on a printed
hexagonal `W1L` callout** that the architect drew. At 2200% (`tag_zoom.png`) the tag
reads `W1L` unambiguously and his highlighter sits **below** the glyphs, so it does
not obstruct OCR. Tag geometry is roughly 9x10 pt on a 792x1224 page.

An earlier hypothesis that colour keyed one swipe per window is **disproved**:
distinct cyan blobs per floor are 9/24/11/2/6 against a tally of 28/33/29/29/29.
Colour keys the *type* in his notation; it does not count openings, so blob-counting
is not a valid proxy.

**Consequence:** build a printed-tag detector, not a highlighter detector. Pages are
pure raster (one 3300x5100 JPEG at 300 dpi, zero text objects), so this is symbol
detection + OCR, not text extraction.

## F69 — The output contract for this trade is a per-type QUANTITY

`TakeOff sent to Supplier - Windows and Balcony Doors.pdf` is what Bill delivers: a
faxed QUOTE REQUEST to Sonora Valley Window Works, from Bill Dunn. The architect
preprints a grid of type elevations (dimensions, `FIXED`/`SCREEN` panel labels, swing
arcs, the same hexagon tag as the plans) and Bill hand-writes **one quantity per type**
("19 each") plus **`T` marks on the individual panes needing tempered glass**.

Full loop: tags on plans -> per-floor tally -> per-type quantity on the schedule ->
fax to supplier.

**Counts alone are not a sendable deliverable.** Output must be a per-type quantity
keyed to the architect's own type codes.

**Open for the client (do not guess, CLAUDE.md §4):** the `T` marks are per-pane, so
two windows of one type could need different panes tempered depending on location.
Ask whether tempering is decided per type or per opening — that decides whether a
per-type quantity is complete output or whether location must also be reported.

## F72 — Bill Dunn: window mark-bubble counting on the Aqua Vista scans
New `takeoff_engine/marks.py` counts the sheet's NATIVE window tag callouts on pure-raster
scans: render 300 dpi -> orient (tesseract OSD, plus a 180-degree retry when no code reads — it
picked 270 for 90 on page 4) -> deskew -> seed a template from the sheet's own clean bubbles ->
GRAYSCALE match (contrast-normalised, so faint tags survive: 0.46 binary vs 0.77 grayscale) ->
ring + per-band gate -> mask the outline away -> group identical codes -> OCR ONE aligned
average per group, snapped to the schedule's own MARK column. Highlighter-immune by
construction (HSV value channel; 0.60% of page 1 is highlighter, only 0.015% is both coloured
and below the ink threshold), so F67's answer key is never an input. `symbols_suggest` keeps its
vector path and falls back to this when a page has neither strokes nor words; the MARK/QTY table
reader is generalised to WINDOW TYPE / QTY with QTY optional and a lookalike-tolerant mode for
OCR'd schedules — F41's 9/9 benchmark (W1..W5, qty 3/1/3/1/1) is unchanged.
SCORED vs F68's key (my independent transcription of all five margin tallies matches it
exactly): 129 named of 185. W1R 15/15 exact on every floor; W1L 114/148; W2L 0/12; W3L 0/2;
W4 0/8. 165 bubbles found in total — 27 read as strings not in the schedule (a MIXED bucket: some are
the diamond WALL tags working as intended, some are real window marks that misread, e.g. a W1L
read as "VIL" on floor 5 — not separated by eye, so no split quoted), 9 unreadable, and
25 openings with no detection (all 7 on floor 1 eye-confirmed as openings the architect never
tagged, which Bill marks by hand).
TWO BUGS FIXED, both measured. (a) W2L was silently counted as W1L: whole-image correlation
cannot separate codes differing in one of three characters (W1L-W2L as close as 0.142 vs
W1L-W1L up to 0.395); scoring the worst of four column bands separates them (0.393 vs 0.454).

WRONG marks; removing it costs 139->129 named but takes wrong names to ZERO. Deliberate trade —
a wrong mark reaches the supplier silently, an unread group is one click to name in the panel.

READING, not finding — per-glyph matching against exemplars confirmed on the same sheet,
including ones the estimator names by hand. A 2-character code (W4) cannot be told from a
truncated 3-character read by string logic alone. Related: naming is withheld entirely when a
